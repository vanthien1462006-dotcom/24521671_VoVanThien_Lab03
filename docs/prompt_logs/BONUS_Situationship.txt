  ## Part 8. Bonus Exercise: "Hẹn Hò Nhưng Không Yêu" Situationship FSM

  ### 8.1 Overview
  `SituationshipAnalyzer` (src/homeworks/BonusSituationship/) replaces the
  boolean soup `isDating && !isLoved && !hasTitle` with a finite state machine
  of four phases. Effort is asymmetric: Em's tries weigh 0.1, Ai đó's parts
  weigh 50. Scores and the red flag are derived during render from raw inputs
  and an immutable signal log. While the phase is DATING_NO_LOVE, a 5-second
  reply timer (abortable) moves the phase to GHOSTED_EXIT; sending a message
  restarts it, and unmount or Unbind cancels it. Source: slides 31 and 32.

  ### 8.2 Contract
  ```js
  /**
   * @typedef {'FRIENDS' | 'DATING_NO_LOVE' | 'OFFICIAL_LOVE' | 'GHOSTED_EXIT'}
  RelationshipPhase
   */

  /**
   * @typedef {'START_DATING' | 'CONFIRM_LOVE' | 'GHOST_TIMEOUT' | 'UNBIND' |
  'RESET'} RelationshipEvent
   */

  /**
   * @typedef {Object} EffortSignal
   * @property {string} id           crypto.randomUUID()
   * @property {'EM' | 'AI_DO'} actor
   * @property {'EM' | 'AI_DO'} type Same value as actor (slide 32 log entry
  shape).
   * @property {number} steps
   * @property {number} multiplier   0.1 for EM, 50 for AI_DO.
   * @property {number} impact       steps × multiplier.
   */

  export {};
  ```

  ### 8.3 Invariants
  1. The UI is `<article aria-label="Hẹn Hò Nhưng Không Yêu Analyzer"
  lang="vi">` inside a section with `<h2>Bonus Exercise: Situationship
  FSM</h2>`, rendered only in the `bonus` view.
  2. Phase is one state value of RelationshipPhase, changed only through
  `transition(phase, event)`. No isDating, isLoved or hasTitle anywhere.
  3. Raw state: phase, myTries, rivalTries, signals. myImpact = myTries × 0.1,
  rivalImpact = rivalTries × 50, isRedFlag = phase === 'DATING_NO_LOVE' &&
  myImpact < rivalImpact, all derived during render. No effect synchronizes
  derived values.
  4. One effect, deps [phase, myTries]: only in DATING_NO_LOVE it creates an
  AbortController, waits 5000 ms with the abortable delay, then applies
  GHOST_TIMEOUT; its cleanup aborts. AbortError is ignored.
  5. Signals are appended with [...prev, signal]; the list shows the last 10,
  newest first, keyed by id.
  6. Both number inputs have visible labels through useId, read valueAsNumber
  and never store NaN or negative values.
  7. `<output role="status" aria-live="polite">` shows '[RED-FLAG] Red Flag:
  Hẹn hò nhưng không yêu — Giải phóng bộ nhớ!' or '[OK] Stable', and the phase.
  8. A `<meter min="0" max="1">` shows Em's share of effort impact with a
  visible label and a text value.
  9. Only the short phrases of slides 31 and 32 are used; no song lyrics are
  added.

  ### 8.4 Expected results
  transition(phase, event):
  | phase | event | Expected |
  | --- | --- | --- |
  | FRIENDS | START_DATING | DATING_NO_LOVE |
  | DATING_NO_LOVE | CONFIRM_LOVE | OFFICIAL_LOVE |
  | DATING_NO_LOVE | GHOST_TIMEOUT | GHOSTED_EXIT |
  | FRIENDS | UNBIND | GHOSTED_EXIT |
  | DATING_NO_LOVE | UNBIND | GHOSTED_EXIT |
  | OFFICIAL_LOVE | UNBIND | GHOSTED_EXIT |
  | GHOSTED_EXIT | RESET | FRIENDS |
  | OFFICIAL_LOVE | GHOST_TIMEOUT | OFFICIAL_LOVE |
  | GHOSTED_EXIT | START_DATING | GHOSTED_EXIT |
  | FRIENDS | CONFIRM_LOVE | FRIENDS |
  | 'NOPE' | START_DATING | throws TypeError |

  computeImpacts(myTries, rivalTries): (100, 1) → { myImpact: 10, rivalImpact:
  50, emShare: 1/6 }; (500, 1) → { 50, 50, 0.5 }; (0, 0) → { 0, 0, 0 }.
  isRedFlag(phase, myImpact, rivalImpact): ('DATING_NO_LOVE', 10, 50) → true;
  ('DATING_NO_LOVE', 50, 50) → false; ('OFFICIAL_LOVE', 10, 50) → false;
  ('FRIENDS', 10, 50) → false.
  createSignal('EM', 1, () => 'id-1') → { id: 'id-1', actor: 'EM', type: 'EM',
  steps: 1, multiplier: 0.1, impact: 0.1 } frozen; createSignal('AI_DO', 1, …)
  impact 50; createSignal('X', 1, …) throws TypeError.
  appendSignal(log, s) returns a new frozen array, input unchanged.
  latestSignals(log, 10) returns at most 10, newest first.
  sanitizeCount(valueAsNumber): NaN → 0; -3 → 0; 2.7 → 2; 42 → 42.

  ## Bonus Exercise: Hẹn Hò Nhưng Không Yêu Situationship FSM

  `SituationshipAnalyzer` models a relationship as a finite state machine with
  four phases (FRIENDS, DATING_NO_LOVE, OFFICIAL_LOVE, GHOSTED_EXIT). The red
  flag is derived during render from the phase and two effort counters, never
  stored. A 5 second ghosting timer is an abortable promise, and the effect
  cleanup aborts it. Every effort signal is appended to an immutable log.

  ### Source layout

  ```
  src/
    shell/resolveView.js             VIEWS gains { id: 'bonus', label: 'Bonus
  Exercise' } (and resolveView.test.js)
    App.jsx                          renders SituationshipAnalyzer for the
  bonus view
    styles/tokens.css                "Situationship (Bonus)" token group
    homeworks/
      BonusSituationship/
        situationship.contract.js    JSDoc typedefs only
        situationshipModel.js / .test.js   PHASES, EFFORT_WEIGHTS, transition,
  computeImpacts, isRedFlag, createSignal, appendSignal, latestSignals,
  sanitizeCount, with tests
        SituationshipAnalyzer.jsx    the component: inputs, meter, buttons,
  ghost timer, signal log
        SituationshipAnalyzer.module.css   mobile-first layout
  ```

  The view id `#bonus` lives in `src/shell/resolveView.js`. The abortable
  `delay` is imported from `src/homeworks/GrandPiano88/replay.js`.

  ### Constraints

  - The phase is one value changed only by the pure `transition(phase, event)`.
  An unknown phase and event pair returns the current phase, and an unknown
  phase throws a TypeError. There are no boolean flags for the relationship
  (check C13).
  - Transitions: FRIENDS + START_DATING gives DATING_NO_LOVE; DATING_NO_LOVE +
  CONFIRM_LOVE gives OFFICIAL_LOVE; DATING_NO_LOVE + GHOST_TIMEOUT gives
  GHOSTED_EXIT; FRIENDS, DATING_NO_LOVE and OFFICIAL_LOVE + UNBIND give
  GHOSTED_EXIT; GHOSTED_EXIT + RESET gives FRIENDS.
  - Weights: `myImpact = myTries * 0.1` and `rivalImpact = rivalTries * 50`.
  The start values 100 and 1 give 10 against 50.
  - `isRedFlag(phase, myImpact, rivalImpact)` is true only in DATING_NO_LOVE
  when `myImpact` is below `rivalImpact`. It is computed during render. "Xác
  nhận yêu" is offered only when it is not a red flag.
  - The meter shows Em's share of the total impact (0 when both are 0).
  - One effect with deps `[phase, myTries]` starts the 5 second wait only in
  DATING_NO_LOVE. It creates an `AbortController`, and the cleanup aborts it,
  so a new try, a phase change or leaving the page cancels the old timer (check
  C14).
  - The signal log is immutable: each signal is a frozen object with an id from
  `crypto.randomUUID`, appended as `[...log, signal]`. The list shows the last
  10, newest first.
  - The Vietnamese UI text is inside an element with `lang="vi"`, English
  phrases carry `lang="en"`, the result is an `<output role="status"
  aria-live="polite">`, and the two number inputs have labels linked with
  `useId`.

  ### How to test

  These steps are done by hand in the browser at
  `http://localhost:5173/#bonus`.

  1. Open the page. The phase is DATING_NO_LOVE, the red-flag text is shown,
  the meter is low and the numbers read "Em: 10.0 · Ai đó: 50.0". There is no
  "Xác nhận yêu" button.
  2. Wait 5 seconds without touching anything. The phase becomes GHOSTED_EXIT,
  the text is "[OK] Stable", and only "Bắt đầu lại" remains next to the signal
  buttons.
  3. Timer reset: reload and click "Gửi tin nhắn" every 3 seconds for about 15
  seconds. The phase stays DATING_NO_LOVE and the signal log grows, newest
  first.
  4. Set "Em cố (số lần)" to 500. The text becomes "[OK] Stable", and "Xác nhận
  yêu" appears. Click it within 5 seconds, before the ghosting timer fires, to
  reach OFFICIAL_LOVE (no timer runs there).
  5. Click "Unbind & Free Memory". The phase becomes GHOSTED_EXIT at once. "Bắt
  đầu lại" gives FRIENDS, and "Bắt đầu hẹn hò" gives DATING_NO_LOVE, which
  starts the timer again.
  6. Unmount: reload, and within 5 seconds click HW1 in the nav. Wait 6
  seconds. The Console stays clean.

  ### Known limits

  - Phase names and weights follow the slide 32 reference code (FRIENDS /
  DATING_NO_LOVE / OFFICIAL_LOVE / GHOSTED_EXIT, 0.1 against 50), not the
  alternative names and multipliers in the text of slide 31.
  - "Dừng Lại" in slide 32 is implemented as the "Unbind & Free Memory" button.
  - Only short phrases from the slides are used; no song lyrics.
  - Only `phase` and `myTries` restart the 5 second timer, as in slide 32. "Ai
  đó một phần" changes the numbers and the log but does not restart it.
  - The signal buttons stay enabled in GHOSTED_EXIT, so the log can still grow
  there until "Bắt đầu lại" is clicked.
  - `transition` reads events from a plain object, so an event named like an
  `Object.prototype` property (`constructor`, `toString`) returns that property
  instead of the current phase. The page only sends the five known events, so
  this cannot happen from the UI.
  - Reloading the page resets the phase, the counters and the log; nothing is
  stored.
